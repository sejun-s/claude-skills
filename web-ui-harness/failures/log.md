## 측정 도구에서 발견·수정한 문제 (T1 중)
- `qa.mjs` 한국어 끊김이 한글|라틴 경계("열립니다|(contact")를 어절 분할로 오검출 → 두 글자가 모두 한글일 때만 집계하도록 수정.
- `touch-target<24px`가 푸터/내비 텍스트 링크로 6/6·20폭 전부 검출(변별력 없음) → WCAG 2.2 SC 2.5.8 간격 예외 적용(24px 원이 다른 타깃과 겹칠 때만). 인접 소형 타깃은 검출, 단독 20px은 통과 확인(픽스처).
- 수정 후 재측정: 6개 run의 Mechanical 결함은 한국어 고아 줄 3건뿐(가로 오버플로·잘림 0건).

## 가설 영향 (중요)
- **"한국어 줄바꿈이 가장 확실한 gap" 가설은 T1 baseline에서 지지되지 않았다.** A(Plain Claude)도 6/6 `lang="ko"` + `word-break: keep-all`을 기본 적용했고 제목류 어절 분할은 0건이다. 남은 것은 고아 줄(마지막 줄이 1~2글자) 수준이며, 'text-wrap: balance/pretty'는 B만 일부 사용(B 3/3, A 0/3).
- 따라서 한국어 모듈은 **T3(장문 한국어)와 T5 결과 전에 확정하지 않는다.** 가능성이 남은 영역: 장문 본문의 행간·줄 길이·한영/숫자 혼용, 고아 줄. 근거는 T3 baseline에서 확인.
- 재사용 도구가 못 푼다는 증거(gap-matrix)는 유지되지만, "기본 모델이 이미 처리한다"는 반증이 생겼으므로 우선순위를 낮춘다.
