## 측정 도구에서 발견·수정한 문제 (T1 중)
- `qa.mjs` 한국어 끊김이 한글|라틴 경계("열립니다|(contact")를 어절 분할로 오검출 → 두 글자가 모두 한글일 때만 집계하도록 수정.
- `touch-target<24px`가 푸터/내비 텍스트 링크로 6/6·20폭 전부 검출(변별력 없음) → WCAG 2.2 SC 2.5.8 간격 예외 적용(24px 원이 다른 타깃과 겹칠 때만). 인접 소형 타깃은 검출, 단독 20px은 통과 확인(픽스처).
- 수정 후 재측정: 6개 run의 Mechanical 결함은 한국어 고아 줄 3건뿐(가로 오버플로·잘림 0건).

## 가설 영향 (중요)
- **"한국어 줄바꿈이 가장 확실한 gap" 가설은 T1 baseline에서 지지되지 않았다.** A(Plain Claude)도 6/6 `lang="ko"` + `word-break: keep-all`을 기본 적용했고 제목류 어절 분할은 0건이다. 남은 것은 고아 줄(마지막 줄이 1~2글자) 수준이며, 'text-wrap: balance/pretty'는 B만 일부 사용(B 3/3, A 0/3).
- 따라서 한국어 모듈은 **T3(장문 한국어)와 T5 결과 전에 확정하지 않는다.** 가능성이 남은 영역: 장문 본문의 행간·줄 길이·한영/숫자 혼용, 고아 줄. 근거는 T3 baseline에서 확인.
- 재사용 도구가 못 푼다는 증거(gap-matrix)는 유지되지만, "기본 모델이 이미 처리한다"는 반증이 생겼으므로 우선순위를 낮춘다.

## T3 Baseline (brief v0.2; A×3, B×3) — 2026-10-02
- **F-005 해결 확인:** 화면 텍스트가 `content.md`에 없는 문구를 추가한 run **0/6**, 구조 표기([1]·[소제목] 등) 유출 0/6 (T1은 6/6 추가). 규칙 문장 한 줄이 효과가 있었다. 한계: 검사는 4글자 미만 추가와 누락/순서는 보지 않음. `<title>`은 비교 대상에서 제외(A-3만 제목 일부 사용).
- 본문 타이포는 A·B 모두 거의 같은 값: 본문 18–21px, 행간 1.85–1.9, 문단 폭 592–684px, `word-break: keep-all` 6/6, `text-wrap: balance` 6/6(`pretty`는 B-1·B-2), 다크 모드 지원. **정량적으로 A≈B**.
- Mechanical: 가로 오버플로·잘림 0건. 고아 줄(마지막 줄 ≤2글자): A 3/3(byline·목록·링크, 320–576px), B-3 1건(byline @320). 터치 타깃 24px 미만: A-2, B-2(384–576px). `impeccable detect`: B-1에서 `low-contrast` 5건(에이전트는 다크모드 정적 비교 오탐으로 판단, 미검증).
- 한국어 어절 중간 끊김 0/6 (`keep-all` 효과).
- **정정:** 앞선 대화에서 T3 첫 화면 스크린샷 5장을 run에 대응시켜 "3/6에서 제목이 '멈추기 / 전에'로 끊긴다"고 서술했으나, 병렬로 읽은 이미지의 대응이 계산 데이터와 맞지 않아 **그 서술은 철회**한다. 아래 F-009는 DOM에서 추출한 줄바꿈 데이터만 근거로 한다. (T1의 run별 서술은 보고 내용·전체 페이지 이미지와 교차 확인되어 유지.)

### F-009 — 한국어 제목의 의미 단위 줄바꿈 (후보 → 승격 후보)
측정: 각 run의 `h1`을 폭별로 글자 단위 Range로 줄 분할(`word-break: keep-all`, `text-wrap: balance` 적용 상태).

| task | 끊긴 의미 단위 | 발생 |
|------|----------------|------|
| T1 hero "설비 로그에서 고장의 징후를 먼저 찾아냅니다" | "고장의 / 징후를" | **A 3/3 @1440**(데스크톱), B 3/3 @768, B-2 @375, A는 @375·1024도 |
| T3 제목 "로그 한 줄이 라인을 멈추기 전에 — 예지 정비가 …" | "멈추기 / 전에" (A-1 @768·1440, A-3 @375), "예지 / 정비가" (A-1, B-1, B-2, B-3 @375) | 6개 run 중 5개가 3개 폭 중 1개 이상에서 발생 (A-2만 없음) |

- 어절 경계는 `keep-all`이 지키지만 **구(phrase) 단위**는 지키지 못한다. `text-wrap: balance`도 보장하지 못함(A도 사용). 조건 B는 데스크톱 hero에서만 우연히 맞았고 태블릿·모바일에서 동일 문제.
- `qa.mjs`의 어절 중간 끊김 검사로는 검출되지 않는다(어절 경계에서 끊기므로).
- **승격 기준 점검:** 2개 task(T1, T3) ✓ / 기존 도구(keep-all, text-wrap, Impeccable, frontend-design)가 못 풂 ✓(0건 해당 규칙, `detect`에 규칙 없음 — 소스 grep 및 프로브) / 두 조건 모두 발생 ✓. **단, "의미 단위"의 판정은 제 주관**이며 사용자 확인이 필요하다.
- 승격 후보 기능(최소): (a) 제목류의 구 단위를 `<span style="white-space:nowrap">`(또는 `&nbsp;`)로 묶는 작성 규칙 + 폭 320/375/768/1024/1440에서 제목 줄바꿈을 추출해 보여주는 측정, (b) 판정은 사람/LLM 리뷰.

## 가설 업데이트
- 한국어 gap 가설을 **"한국어 줄바꿈 일반"에서 "제목의 구 단위 줄바꿈(F-009) + 좁은 폭의 고아 줄"로 좁힌다.** 어절 분할과 본문 가독성(T3)은 기본 모델이 이미 처리한다.
- 스킬 스택(B)은 T1에서 A보다 순위가 높았으나 카피 교란이 있고, 첫 화면의 신뢰 증거(Q4)·대상 명시(Q2)는 6/6 미해결 → 이 영역이 Design Decision Layer 후보. **T1 한 task 근거이므로 T5 baseline 전에는 승격하지 않는다.**
