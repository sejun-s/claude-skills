# 웹사이트 잘 만들기 — 작업 구조

목표: AI로 웹사이트를 만들 때 **디자인 완성도**를 안정적으로 끌어올리고, 그 위에 백엔드를 얹을 수 있는 상태로 넘긴다.
원칙: **새 스킬을 만들지 않는다.** 이미 있는 도구를 순서대로 엮고, 지금까지 실험·QA에서 실제로 드러난 약점을 단계마다 관문(gate)으로 막는다.

> 상태: 구조는 실험 기록(`../failures/log.md`)의 관찰에서 도출한 **제안**이다. 구조 전체가 완성도를 높인다는 증거는 아직 없다(사용자 blind 평가 대기). 단계별 근거 강도를 아래 표에 표시했다.

## 루프 규칙 (하네스 부분)
1. 5단계는 **최대 3회**. 3회 후에도 관문을 못 넘으면 사람에게 넘긴다(무한 반복 금지).
2. **에이전트의 "확인했다/문제없다"는 보고를 근거로 쓰지 않는다.** `check-site.sh`의 출력과 직접 연 스크린샷만 근거다.
3. 수정 후에는 **바뀐 폭에서 다시 렌더**한다(과거 실험에서 대부분의 에이전트가 이 단계를 건너뜀).
4. 폰트가 로드되지 않으면 측정 결과를 무효로 본다(`heading-lines`가 exit 3).
5. 도구·기준을 바꾸면 이전 수치와 섞지 않고 버전을 남긴다.

## 점검 스크립트 (`scripts/`)
```sh
# 사이트 폴더(index.html + fonts/)를 대상으로 근거를 한 번에 모은다. 판정이 아니라 수집이다.
website/scripts/check-site.sh <site_dir> [out_dir]
```
1. 20폭 스윕 + 스크린샷 + Impeccable `detect` (`experiments/tools/qa.mjs`)
2. **글자 크기 하한** (`scripts/min-text-size.mjs`: 12px 미만 경고, 11px 미만이면 수정 필요, 375·1440px 둘 다)
3. 제목 줄바꿈 줄 구성 (`skills/ko-heading-wrap/scripts/heading-lines.mjs`)
4. 사람이 볼 스크린샷 경로 안내

검증: GPT가 만든 알파로그 데모에 실행해 10px/9px 글자(모바일 375px 포함)를 자동 검출함. 전제: Playwright 설치(`PLAYWRIGHT_PATH`), 사이트 `fonts/` 준비.

## 이 구조가 하지 않는 것
- 새 스킬을 만들지 않는다. 지침은 기존 스킬(frontend-design, Impeccable, web-ui-craft)에 맡긴다.
- "AI티 제거"나 미적 개선을 자동 판정하지 않는다. 6단계는 사람이 한다.
- 한국어 제목 줄바꿈 전용 규칙을 강제하지 않는다(`ko-heading-wrap`은 experimental, 영향이 작았음).

## 알려진 한계
- 근거는 단일 페이지 4개 task와 같은 모델 계열 평가에 기댄다. 다중 페이지·디자인 시스템 유지는 다루지 않았다.
- 2·3단계는 아직 써 본 적이 없다. 필요 없다고 판단되면 건너뛰어도 된다.
- 기존 스킬 조합(B)이 plain 대비 낫다는 신호는 있었으나 카피 교란이 있어 확정이 아니다.
