# 6단계 리뷰 관문 (사람이 직접 보고 체크)

기계 검사는 **바닥선**이다. 통과해도 완성도의 증명이 아니다. 하나라도 ✗면 4단계로 돌아간다(루프 최대 3회).

## 시각 (스크린샷을 직접 연다: 375 / 768 / 1440, 첫 화면 + 전체)
- [ ] 첫 화면에서 가장 먼저 읽히는 것이 계약의 초점과 같은가?
- [ ] 첫 화면에 **무엇·누구·다음 행동·믿을 근거**가 모두 있는가?
- [ ] 같은 모양 카드/띠가 이유 없이 반복되지 않는가?
- [ ] 모든 시각물이 **무언가를 설명**하는가? (내용 없는 일러스트·빈 칸·잘린 이미지 없음)
- [ ] 모바일이 축소가 아니라 재구성으로 보이는가?
- [ ] 글자가 읽을 만한가? (`min-text-size` 위반 0, 상태 라벨 포함)

## 내용
- [ ] 의뢰서에 없는 문구·수치·약속이 없는가? (diff)
- [ ] 메뉴/링크가 모두 갈 곳이 있는가?
- [ ] 가상 데이터가 화면에 표시되어 있고, 없는 기능을 성공한 것처럼 보이지 않는가?

## 기술 (`check-site.sh` 출력)
- [ ] 가로 오버플로·잘림 0, 콘솔 오류·에셋 오류 0
- [ ] 폰트 로드 확인(대체 폰트 아님), 글자 크기 하한 통과
- [ ] 대비·focus 표시·reduced motion
- [ ] Impeccable `detect` 경고를 **하나씩 검토**했다(오탐은 이유를 적는다. 예: `cramped-padding`은 내부 래퍼 여백을 못 읽는 오탐이 반복됨)

## 한국어
- [ ] `lang="ko"`, 제목 줄 구성을 375·768·1440에서 눈으로 확인(구가 어색하게 끊기면 해당 구만 묶는다)
- [ ] 표·카드 안 긴 단어가 어절 중간에서 끊기지 않는가? (좁은 열 주의)

## 결론
- 통과 / 4단계로 반려(사유) / 사용자에게 판단 요청(항목)
