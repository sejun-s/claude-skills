# Visual craft — modified excerpts and synthesis

Adapted from Impeccable's craft-floor.md, layout.md, typeset.md and colorize.md, commit 508d7e8955de3b3caf2d8676e85206723d41a887, Apache-2.0. See ../THIRD-PARTY.md and ../LICENSE-IMPECCABLE.txt. Upstream commands and categorical bans have been removed. Apply these criteria to the user's brief rather than treating them as a universal style.

## Composition and rhythm

Layout turns product priority into reading order, grouping, rhythm, and usable space. Diagnose the structural problem before moving boxes.

- Apply the squint test: can the primary element, secondary element and major groups be identified without reading detail?
- Group by meaning. Use proximity before adding containers or decoration.
- Tight groups and generous separation create rhythm. Equal sections do not automatically deserve equal weight.
- Let hierarchy follow product priority rather than framework defaults.
- Repetition should support recognition; vary structure when content or priority changes.
- Responsive behavior is structural: reorder, collapse and reflow while preserving reading and keyboard order.

A full-width product canvas, image-led editorial layout or compact information-led composition can all work. Choose from content, references and brand. Do not require a particular hero topology or a fixed number of 'signature' elements.

## Typography

Typography carries information, hierarchy, and voice. Improve it inside the established visual world.

- Distinguish display, heading, body, label and data roles by size, weight, space and tone together.
- Use the fewest families needed to express those roles. Load only used assets and weights.
- Tune measure and leading to actual language and density. Latin ch ranges are a starting point, not Korean acceptance thresholds.
- Keep reading text readable and zoomable. Avoid tightly tracked, oversized Korean headings that dominate without helping comprehension.
- Test real copy, narrow containers, inline emphasis and long labels. A CSS family string is not proof a font loaded.
- Use tabular numerals for aligned data, not monospace as a costume for 'technical'.

## Color and visuals

Build roles, not a bag of swatches: canvas, primary/secondary text, action, focus, borders and semantic states.

- Choose color dosage from the product and experience; retain confirmed brand commitments.
- Accent should clarify priority rather than decorate unrelated content.
- Verify computed text contrast: ordinary text ≥4.5:1, large text ≥3:1; interactive indicators also need adequate contrast.
- Status needs a label, shape or icon as well as color.
- A product visual should contain understandable content. Placeholder rectangles, unlabeled charts and repetitive icon tiles rarely explain a service.
- Shadows express elevation; borders express grouping. Use them intentionally.
- Selection, focus, underline offset and data alignment belong to the same visual system.

## Motion and states

Start from visible content. Motion can reveal a relationship or respond to an action, but must not conceal important content until a screenshot catches up. Respect reduced motion.

Controls need their real states. Forms need validation, recovery and honest completion. A demo without a sending service must offer a useful local action rather than pretend to transmit.

## Screen critique

Look before reading detector output. Name the visible issue, affected region, and concrete change. Capture again after fixing. A clean mechanical scan is a floor, not proof of hierarchy, rhythm or distinctive design.

Ask: What leads? Which element ignores the content? What feels underdeveloped? Which graphic communicates rather than fills space? Does mobile preserve the important relationship?
