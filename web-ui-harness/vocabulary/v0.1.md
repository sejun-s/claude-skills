# Operational Design Vocabulary v0.1 — 초안 (사용자 검토 대기)

목적: "modern", "calm" 같은 라벨을 실행·검증 가능한 정의로 바꾼다. 라벨만 저장하면 모호한 단어를 다른 모호한 단어로 번역한 것에 불과하다.

## 지위와 읽는 법
- 모든 항목은 **candidate**다. 출처는 사용자 선호 데이터셋 5건(Urbanblue, Apple Korea, Enhans, Goodai Global / 비선호: 움버거앤윙스, SmartMind AI, Villa Oasis)이 전부이고, 표본이 작아 일반 법칙이 아니다. 사용자 승인 전에는 Harness 규칙으로 쓰지 않는다.
- **관찰(사용자가 말한 이유)과 해석(내가 추론)을 분리**한다. 해석에는 confidence를 붙인다. 수치는 근거가 없으면 쓰지 않고 "Baseline에서 보정"으로 둔다.
- 검증 방식 표기: **M** = 기계 측정 가능(qa.mjs/Impeccable 등) / **C** = Design Contract QA(의도한 계약과 구현의 일치) / **H** = 사람 판단만 가능. 품질의 최종 판정은 H(외부 신호)이며, M/C 통과는 품질 보증이 아니다.
- 구성: label / operational definition / hard constraints / preferred range / relational rules / anti-patterns / exceptions / verification.

## 0. 공통 전제
- 이 vocabulary는 "좋은 디자인"이 아니라 **이 사용자가 선호했던 방향**의 정의다. 비선호 사례는 "나쁜 디자인"이 아니라 "이 사용자의 목적과 맞지 않음"으로만 기록한다.
- 상반된 쌍(예: dynamic-not-playful)은 한쪽을 줄이는 규칙이 아니라 **둘 사이의 경계를 정의**한다.

## V-01 clear (첫눈 전달력)
- 출처 — 관찰: Villa Oasis는 동적 요소는 좋았으나 "첫눈에 회사가 무엇을 하는지 전달하는 힘이 부족". 해석: motion/감성보다 **무엇을 하는 곳인지**가 우선 (confidence 0.8, 사용자 발언 직접 근거).
- operational definition: 첫 viewport에서 (1) 무엇을 제공하는지 (2) 누구를 위한 것인지 (3) 다음 행동이 무엇인지가 스크롤 없이 식별된다.
- hard constraints: 첫 viewport 안에 제품/서비스 범주를 직접 명시하는 텍스트 또는 제품 시각물이 존재한다. 은유/슬로건만으로 범주를 대체하지 않는다.
- preferred range: 메시지 1개가 지배(아래 V-04). 보조 문구는 범주 설명을 돕는 용도.
- relational rules: motion/비주얼이 늘수록 범주 명시 문구의 위치·대비를 먼저 점검한다. 동적 요소가 메시지와 경쟁하면 동적 요소를 낮춘다.
- anti-patterns: 추상 슬로건만 있는 hero, 브랜드명만 큰 hero, 범주를 알 수 없는 영상 루프.
- exceptions: 브랜드 인지도가 이미 압도적인 경우(Apple류)는 제품 시각물이 범주 명시를 대신할 수 있다.
- verification: **C** (계약에 "범주 명시 위치"를 기록하고 렌더에서 확인) + **H** (5초 테스트: 처음 보는 사람이 업종을 맞히는가).

## V-02 calm
- 출처 — 관찰: Enhans "과도하지 않은 현대적", Goodai "깔끔한 composition", 움버거앤윙스는 "너무 경쾌". 해석: 동시 자극의 양과 채도/모션 에너지를 낮게 유지 (confidence 0.6).
- operational definition: 한 viewport에서 동시에 움직이거나 강한 대비로 시선을 끄는 요소 수가 제한되고, 모션이 있더라도 반복 주기가 느리고 진폭이 작다.
- hard constraints: 같은 viewport에서 독립적으로 움직이는 요소 수는 정의된 상한 이하(상한은 Baseline에서 보정, 초기 가설 1~2개). 자동 재생 모션은 `prefers-reduced-motion`을 존중.
- preferred range: 강한 채도의 면은 최대 1개 계열. 모션은 정보를 드러내는 용도일 때만.
- relational rules: V-05(dynamic-not-playful)와 함께 평가. calm이 높아질수록 V-08(minimal-not-empty) 위반 위험이 커지므로 시각물/제품 UI로 보강.
- anti-patterns: 장식용 float/parallax, 섹션마다 등장 애니메이션, 다색 강조.
- exceptions: 브랜드 목적이 에너지 자체인 경우(예: 엔터테인먼트) — 이 사용자의 기본 선호가 아님.
- verification: **M** 일부(동시 애니메이션 요소 수, reduced-motion 처리, 강조 색 개수 — 현재 도구 미구현) + **H**.

## V-03 structured
- 출처 — 관찰: Enhans "복잡한 정보를 정돈", Goodai "깔끔한 composition". 해석: 정렬·그리드·반복 규칙이 읽혀 정보 위치를 예측할 수 있음 (confidence 0.7).
- operational definition: 주요 요소의 좌/우/상 가장자리가 소수(≤3)의 정렬선에 맞고, 같은 역할의 요소는 같은 간격 규칙을 쓴다.
- hard constraints: 같은 역할 요소 간 spacing/정렬 규칙의 의도 없는 불일치 없음.
- preferred range: 정렬선 수와 간격 단계는 DESIGN 토큰으로 선언하고 그 안에서 사용.
- relational rules: **Controlled Variation** — 규칙을 깨는 요소는 의도(강조/리듬)를 decision log에 기록해야 하며, 기록 없는 불일치는 결함 후보.
- anti-patterns: 모든 섹션이 동일 구조의 반복(단조로운 리듬), 비슷하지만 다른 간격이 무작위로 섞임.
- exceptions: 의도된 비대칭 구성(V-07)은 정렬선 규칙이 다른 축에서 성립하면 허용.
- verification: **M** 부분 가능(간격 값 분포, 정렬선 수 — 미구현) / **C**(선언한 토큰 대비 실제 값) / **H**.

## V-04 hierarchy
- 출처 — 관찰: Apple Korea "제품 강조가 쉬움", Enhans "복잡한 정보를 정돈". 해석: 주 메시지/초점이 하나로 정해져 있음 (confidence 0.7).
- operational definition: 한 viewport에 주요 초점(primary focal point)이 하나 있고, 그 외 요소의 시각적 지배력(크기·대비·위치·여백 중 필요한 수단)이 의도적으로 낮다.
- hard constraints: 주 CTA와 보조 CTA가 동일한 강조 수준을 갖지 않는다. 동일 강조 제목이 한 viewport에 다수 있지 않다.
- preferred range: 위계 수단은 scale·weight·spacing 우선, 장식(그림자/테두리/배경색)은 나중.
- relational rules: DG-007형 — 여러 요소가 비슷한 visual weight → 초점 선택 후 나머지를 낮춘다.
- anti-patterns: 위계를 모든 요소를 카드로 감싸 해결하려는 것, 강조색 다수 경쟁.
- exceptions: 동등한 항목의 탐색이 핵심인 UI(대시보드, 비교표)는 다수 초점이 정상.
- verification: **C**(계약에 초점 요소 지정, 렌더에서 실제 지배 여부) + **M** 일부(heading 대비/CTA 스타일 비교) + **H**. 수치 규칙(예: heading ≥ body×N)은 만들지 않는다.

## V-05 dynamic-not-playful
- 출처 — 관찰: Enhans의 "단순 반복 영상 hero" 선호, Villa Oasis 동적 요소 긍정, 움버거앤윙스 "너무 경쾌" 기피. 해석: 움직임은 **무엇을 하는지 보여주는 용도**일 때 좋고 감정/놀이 톤으로 가면 기피 (confidence 0.6).
- operational definition: 움직임이 제품 동작·정보 관계·공간적 연속성을 설명하는 데 쓰이며, 톤은 중립~차분(탄성/바운스/캐릭터성 없음).
- hard constraints: 모션마다 목적 1줄(드러냄/설명/유도/연속/시그니처)을 계약에 기록. 목적 없는 모션은 제거 후보.
- preferred range: 반복 루프형은 짧고 단조로운 패턴 허용.
- relational rules: V-01과 충돌 시 V-01 우선(motion이 범주 전달을 가리면 낮춘다).
- anti-patterns: 바운스/탄성 easing, 의미 없는 float, 모든 섹션 scroll reveal, 과도한 parallax. (Impeccable `bounce-easing` 등과 일부 겹침)
- exceptions: 브랜드 목적이 유희인 경우.
- verification: **M** 일부(easing 종류는 Impeccable로 검출) / **C**(모션 목적 기록) / **H**.

## V-06 informative-not-text-heavy
- 출처 — 관찰: SmartMind AI "지나치게 text 기반", Apple Korea/Enhans는 간결하면서 전달됨. 해석: 정보량을 줄이는 것이 아니라 **정보의 표현 방식을 텍스트 외로 분산**하는 것을 선호 (confidence 0.65, 후보 DG-002와 연결).
- operational definition: 핵심 정보 단위마다 표현 수단(텍스트/이미지/제품 UI/다이어그램/숫자/모션/비교/프로세스)을 선택한 근거가 있고, 연속된 텍스트 블록이 첫 viewport를 지배하지 않는다.
- hard constraints: 첫 viewport에 텍스트만으로 이뤄진 구간이 지배적이지 않다(기준은 Baseline 보정; 텍스트 면적 비율은 측정 후보).
- preferred range: 추상적/기술적/B2B 서비스는 설명 레이어(제품 UI, 다이어그램, 워크플로, 사례, 비교)를 둔다.
- relational rules: 자명한 제품 → 시각 우세 + 문구 감소 가능(Apple식). 복잡한 서비스에 같은 구조를 그대로 적용하지 않는다.
- anti-patterns: 정보가 많다고 문단/불릿만 추가, 텍스트 카드 격자만으로 구성.
- exceptions: 장문 콘텐츠 페이지(T3)는 텍스트가 본체 — 대신 타이포 품질로 평가.
- verification: **M** 후보(텍스트 대 비텍스트 면적 비, 연속 텍스트 길이 — 미구현) / **C** / **H**.

## V-07 distinctive-not-experimental
- 출처 — 관찰: Urbanblue "여러 이미지를 규칙적이면서도 불규칙하게, 기존과 다른 구성", Villa Oasis "designer/agency 감성 자체는 목표가 아님". 해석: 개성은 원하지만 실험성/작가성이 전달력을 해치는 수준은 비선호 (confidence 0.6).
- operational definition: 페이지에 Primary Signature Device가 정확히 1개 있고(타이포 주도/에디토리얼 그리드/이미지 처리/비대칭/제품 UI/데이터 시각화/고유 인터랙션 중), 나머지는 시스템에 종속된다.
- hard constraints: Signature는 선언된 1개. 이를 위해 V-01(clear)을 희생하지 않는다.
- preferred range: 규칙적 틀 안의 의도된 불규칙(Urbanblue형) — 틀이 읽혀야 한다.
- relational rules: 기계적 반복을 피하기 위한 Controlled Variation은 Signature를 강화하는 방향으로만.
- anti-patterns: 평균적 SaaS hero(중앙 정렬 + 부제 + CTA 2개) — 단, 근거가 있으면 유지 가능(justify-or-change). 여러 개의 Signature 병렬.
- exceptions: 브랜드가 실험성을 목적으로 하는 경우.
- verification: **C**(Signature 선언과 렌더 일치) + **H**(blind 비교). M 불가.

## V-08 minimal-not-empty
- 출처 — 관찰: Apple Korea "단순함, 제품 강조", SmartMind AI 기피. 해석: 요소 수 감소는 좋아하나 시각적 내용(제품/이미지/UI)이 없는 빈 구성은 아님 (confidence 0.55).
- operational definition: 요소 수는 적되, 첫 viewport에 시각적 실체(제품 시각물/이미지/UI/데이터 중 하나 이상)가 있고 여백이 초점을 만드는 데 쓰인다.
- hard constraints: 텍스트만 있는 hero 금지(예외: 콘텐츠 페이지).
- relational rules: V-02(calm)를 높일수록 시각적 실체를 먼저 확보.
- anti-patterns: 큰 여백 + 짧은 문구만 있는 화면(여백이 초점이 아니라 공백).
- exceptions: 장문 읽기 페이지.
- verification: **M** 후보(첫 viewport 내 이미지/미디어 존재, 텍스트 면적) / **C** / **H**.

## V-09 complexity-separation (candidate DG-001)
- 출처 — 관찰: Urbanblue(시각 풍부) 선호, 복잡한 정보 정돈(Enhans) 선호. 해석: **시각적 복잡도 ≠ 정보 복잡도**; 시각물이 풍부해도 동시에 이해해야 할 핵심 메시지는 제한 (confidence 0.6, 가설).
- operational definition: viewport당 동시에 이해해야 하는 핵심 메시지 수를 선언하고(초기 가설 1), 시각 요소가 많아도 그 수를 늘리지 않는다. 콘텐츠가 복잡하면 장식적 시각 복잡도를 줄인다.
- relational rules: 시각물이 많을수록 텍스트 위계(V-04)를 단순하게.
- anti-patterns: 이미지 다수 + 텍스트 카드 다수 + 모션이 동시에 경쟁.
- verification: **C** + **H**. 반례 수집 필요(가설 상태 유지).
