# UI 디자이너 관점 (읽은 것: 지정 파일 전부. 스크린샷은 보지 않음 -> 아래 시각 판단은 로그 기록 기준)

## 1) 실제 영향 우선순위
확인(로그): proxy 3역 모두 B>A, 5초 테스트 Q2(대상)/Q4(신뢰 증거) 6/6 미해결, F-002/F-004 지적 일치, T3 본문 타이포 A≈B.
추측: 아래 순서는 내 경험 기반 판단.
1. 첫 화면 신뢰 증거·대상 명시(Q2/Q4) - 측정: 5초 테스트로 가능(사람 필요). 영향 최대인데 가장 미착수. T1은 카피 교란이 있어 T1 단독 근거는 약함.
2. 섹션 리듬/시각 목적(F-003, F-004: 정보 없는 대형 면, 균일 카드 반복) - 기계 측정 불가, H 판정만.
3. 에셋 처리(F-002 letterbox, SVG 내 폰트 불일치) - 일부 측정 가능(비율/여백), 주로 H.
4. F-009 제목 구 줄바꿈 - 측정 가능(이미 스크립트). 그러나 영향은 "중간 이하": 디테일 완성도이지 AI 티의 주원인이 아님. 측정이 쉬워서 과대 투자되는 위험.
5. F-008 고아 줄, F-006 detector 오탐, F-007 루프 - 낮음.
F-001은 D-001의 승격 보류에 동의. 단 "6/6 동일"은 시각 리듬 수준의 AI 티 신호일 수 있어 폐기 말고 관찰 유지.
측정 가능: 오버플로, 터치 타깃, 구 쪼개짐, 고아 줄, 본문 타이포 수치. 불가: 위계, 리듬, 신뢰감, "의도가 있음" 전부.

## 2) 6~8시간 가치 있는 일
- A. T5를 3x3 이상 실행해 B vs C(+F-002/003/004 재현 여부 기록). 승격 기준(>=2 task)을 실제로 채울 후보는 여기서 나옴.
- B. Q2/Q4 대응 실험: 신뢰 증거를 요구하는 brief 비수정 상태에서, 콘텐츠에 실제처럼 보이는 가상 값(D-002 지적)을 넣은 T1 v0.3로 B vs "B+짧은 결정 규칙"을 비교. 규칙은 후보만 쓰고 승격 금지.
- C. blind 패키지(아래 3)를 완성도 높게 준비하고 키 분리. v0.2 ko-heading-wrap 재측정 포함.
하지 말 것:
- X1. 사용자 판정 전에 vocabulary 규칙/수치(정렬선 <=3 등)를 Harness 필수 규칙으로 확정.
- X2. F-003/F-004용 "섹션 리듬 검사기"를 임의 임계값으로 구현(측정 불가한 것을 가짜 측정으로 만듦).
- X3. 같은 모델 proxy 패널 순위를 "개선됨" 근거로 인용, 또는 한 장 스크린샷을 병렬로 읽어 run별 결론 내리기(이미 정정 사례 있음).

## 3) blind 평가 패키지
- 쌍: task별 B vs C 위주(비교 대상은 B, D-002). A는 앵커로 task당 1개만. 같은 쌍을 좌우 랜덤, 순서 랜덤, 라벨/파일명/타이틀 제거, 폰트·문구 동일 확인.
- 개수: 15~18쌍 이내, 20분. 쌍당 질문 3개: (1) 어느 쪽이 더 "의도가 있어 보이는가" (2) 실제 쓰고 싶은 쪽 (3) 한 줄 이유(선택). 동률 허용. 별도 "AI가 만든 것 같은가"는 편향 유발이라 마지막에 한 번만.
- 화면: 1440x900 first fold + 전체 페이지 축소본, 375x812 첫 화면. 한 쌍에 데스크톱 먼저, 모바일은 따로 3쌍만.
- 5초 테스트는 별도 세션, task 내용을 모르는 사람 1~2명(프로토콜 한계 인정).
- 편향 통제: 같은 쌍 2~3개를 위치 바꿔 재출제(일관성 점검), 키는 별도 파일, 결과는 방향 신호로만 기록.

## 4) "100% 완료" 조건
혼자 가능: 도구 기계 지표 0결함, 문구 추가 0, 재현 가능한 실험 기록, 패키지 준비, 한계 명시.
불가능: "디자인 품질이 올랐다"는 주장. 이는 사용자 blind 평가(최소 B vs C 쌍에서 C 우세가 일관적이고 모바일에서도 유지)와 task 3개 이상 재현이 있어야만 가능. 따라서 자율 세션의 정직한 종료 문구는 "100% 완료"가 아니라 "판정 대기 상태 완료".
