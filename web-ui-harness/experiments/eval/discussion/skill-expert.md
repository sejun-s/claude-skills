# 스킬 전문가 의견 (표기: [확인]=파일에서 확인, [추측]=추정)

## 1) 약점
**실험 설계**
- [확인] C vs B는 "스킬 지식" 효과와 "측정 스크립트 루프" 효과가 섞여 있다. 대조군(B + "폭별 제목 줄바꿈을 직접 확인하라" 한 줄 + 스크립트만, 지식 없음)이 없다. decisions D-003도 "스크립트가 자기 오류를 잡는 효과"를 스스로 적었다. 어느 부분이 가치인지 미분리.
- [확인] gold는 같은 Claude(작성자)가 만들었고 자명한 수식어-핵심어 위주(ablation 한계란에 본인 기록). 에이전트도 같은 모델이라 gold와 판단이 상관됨 -> 10→1은 과대평가 가능.
- [확인] 단위 = 제목×폭이고 n=조건당 3, 2 task. 같은 제목의 5개 폭은 독립이 아님(의사반복). 통계적 주장 불가, 방향 신호일 뿐.
- [확인] 시각 품질은 미측정. "쪼개짐 감소 = 더 좋은 제목"은 가정이다. nowrap 묶음이 balance를 무력화해 오히려 들쭉날쭉/고아 줄을 만들 수 있다.
- [확인] v0.2는 재측정 전인데 v0.1 결과로 "유지" 판정. 지금 판정은 v0.1에 대한 것.
- [확인] T3의 B 프롬프트에 "재확인" 줄이 추가돼 T1 B와 비교 불가(D-001). 조건 C의 프롬프트 차이는 문서화가 불충분.
- [확인] 모든 시각 판단이 Claude 단독·비blind. proxy 패널은 같은 계열.

**스킬 설계**
- [확인] 스크립트는 에이전트가 넘긴 `--keep` 구만 검사한다. `--keep` 비면 exit 0·"쪼개짐 0건"이 나온다. 즉 에이전트가 묶지 않은/나열 안 한 구는 영원히 미검출. 에이전트가 고른 구를 에이전트가 측정하는 순환 구조 (T3-C-2의 "0건" 오보고도 이 계열).
- [확인] 구 매칭이 공백 제거한 flat 문자열 indexOf라 어절 경계를 가로지르는 우연한 부분 일치(오탐/미탐)가 가능. 줄 구분은 top 차이 >6px 휴리스틱(인라인 블록·첨자에서 오작동 가능 [추측]).
- [확인] 스크립트가 `/opt/node-tools`, `/opt/pw-browsers` 하드코딩. 이 환경 밖에서는 안 돌아감(PLAYWRIGHT_PATH/CHROME_BIN env로만 우회).
- [확인] 구 선정 기준이 "애매하면 묶지 않는다"인데, gold 판정도 같은 주관 -> 판정 기준이 스킬에 있어 gold와 순환.
- [추측] description 트리거 정확도는 전혀 미검증: 실험에서는 파일을 읽게 했지 자동 발동시키지 않았다. 실제 사용 시 로드될지 모름.
- [추측] 오염: leaky=clean 결과로 예시 오염은 배제했지만, 에이전트가 제목 텍스트를 이미 알고 있어 "gold 구 = 제목의 자명한 구"인 것이 진짜 오염 경로. 어려운 구/새 제목(hold-out)이 없음.
- [확인] qa.mjs 변경 이력, 폰트 로컬화 등 측정 환경 변동은 기록됨(양호).

## 2) 6~8시간 가치 높은 3가지
1. **v0.2 재측정 + 위약 대조군**: hold-out 제목 세트(작성자가 에이전트·SKILL 예시와 무관하게 새로 작성, 어려운 구 포함 T5/신규 문장) 위에서 B / B+스크립트만 / C-v0.2. 여기서 "지식 vs 루프"를 분리. 스크립트는 `--keep` 없이도 모든 제목의 폭별 줄 구성을 덤프(+ 1~2글자 고아·짧은 줄 경고)하게 개선하면 순환 구조 완화.
2. **T5 baseline 실행**(brief v0.2): 승격 기준(≥2 task)을 카피 교란 없는 3번째 task로 재점검. 한국어 제목 외 failure(F-002/003/004)의 재현 여부 확인.
3. **blind 평가 패키지 정비 후 대기**: C vs B 라벨 제거 스크린샷 쌍(폭 375/1440, 제목 영역 포함)과 평가 시트를 만들어 사용자 복귀 시 5분에 판정 가능하게. 이것이 유일한 최종 판정 경로다.

**하지 말 것**
1. Design Decision Layer / 다른 failure(Q2·Q4 신뢰 증거) 승격 — T1 한 task, 카피 교란, 근거 부족. 승격 기준 위반.
2. 스킬을 하나로 묶거나 vocabulary(V-01~11)를 SKILL로 이식 — 관찰 근거 없는 candidate를 컨텍스트 비용으로 바꾸는 일. 분리(좁고 측정 가능한 스킬 단위) 유지.
3. Harness 자체 판정으로 "개선됨" 결론 내기(proxy 패널 재가동, 수치 합산 후 선언) 및 실험 중 SKILL/brief/qa.mjs를 사후 수정해 이전 결과와 섞기(변경 시 버전 고정·재측정).

## 3) Harness v0.1 최소 구성
**있음**: skills/ko-heading-wrap/{SKILL.md(약 50줄), scripts/heading-lines.mjs}, experiments/tools(qa.mjs, new-run.sh, collect-run.sh, fonts), benchmarks T1/T3/T5, failures/decisions 로그, protocol.md, vocabulary v0.1(candidate).
**없음**: (a) 버전·변경이력이 붙은 릴리스 정의(예: harness/VERSION, CHANGELOG), (b) 설치 가능한 형태(plugin/skills 디렉터리 + 하드코딩 경로 제거 + 의존성 점검 `doctor` 스크립트), (c) 단일 진입 문서 README(무엇이 승격됐고 무엇이 candidate인지 표 1개), (d) 회귀 픽스처(하드/쉬운 구 포함 fixture + 기대 출력)로 스크립트 자체 테스트, (e) 재현 가능한 `run-ablation` 래퍼, (f) 트리거 평가(should/shouldn't trigger 프롬프트 10여 개).
**권장 규모**: 상시 컨텍스트 비용 = ko-heading-wrap description 한 줄뿐. 본문 SKILL.md는 호출 시에만 로드(<1k 토큰). vocabulary·failure 로그는 스킬에 넣지 않고 `references/`로 두거나 개발용으로만 유지. 승격 스킬 수 = 1. 정의: "v0.1 = 승격된 스킬 1개 + 측정 스크립트 + 이를 검증한 실험 기록 + 알려진 한계 문서".

## 4) '100% 완료' 조건
**혼자 가능**: 재현 가능한 설치/실행(doctor 통과), 스크립트 회귀 테스트, 위약 대조군 포함 ablation 데이터, v0.2 재측정, T5까지 3 task 기록, 트리거 테스트, 한계·버전 문서, blind 평가 패키지 준비, 부작용(오버플로·문구 추가) 0건 검증.
**불가능**: 디자인 품질이 "의도 있는 디자인"으로 올라갔는가(사용자 blind 평가), gold/구 판정의 사용자 합의, 선호 vocabulary 확정(V-10/11은 근거 없음), 다른 평가자 확보. 따라서 하니스 측면에서 정직한 표현은 "v0.1 기능 1개가 기술적으로 검증됐고 품질 판정은 사용자 대기"이지 100%가 아니다. 사용자 blind 평가에서 C가 B보다 유의미하게 선호되지 않으면 ko-heading-wrap은 '측정 유틸'로 격하해야 한다.
