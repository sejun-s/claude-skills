**수정이 필요한 발견**

1. **[P1] 두 blind 패키지가 같은 localStorage를 사용한다.** `experiments/eval/build-human-pack.py:58`과 생성된 두 HTML이 모두 `human-blind-v1`을 쓰며, 항목 ID도 P01부터 중복된다. 제목 패키지 P01에 저장한 이유가 페이지 패키지 P01의 입력란에 그대로 나타나는 것을 Chrome에서 재현했다. 서로 다른 문항 필드가 같은 응답 객체와 JSON에 섞이며, 패키지·버전·평가자 정보도 export에 없다. 패키지별 저장 키와 export 식별자를 분리하고 기존 데이터는 명시적으로 이관해야 한다. 수정 전에는 두 패키지 응답을 동일 브라우저에서 수집하지 않는 편이 안전하다.

2. **[P2] WCAG 소형 타깃 간격 검사가 누락된다.** `experiments/tools/qa.mjs:79–85`는 한 타깃 중심의 반지름 12px 원과 다른 타깃 사각형만 비교한다. 다른 소형 타깃의 24px 원과 겹치는지도 확인해야 한다. 10×10px 버튼 두 개의 중심을 20px 떨어뜨리면 현재 코드는 `smallTargets: []`를 내지만, 두 반지름 12px 원은 겹친다. 소형↔소형 원 중심 간 거리 조건을 추가해야 한다. Inline 등 다른 예외도 현재 코드에 없으므로 결과를 WCAG 전체 적합 판정으로 부르면 안 된다. 기준은 [W3C SC 2.5.8 설명](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)의 Spacing 항목에서 확인했다.

3. **[P2] 실제 한 줄을 세 줄로 오판정한다.** `skills/ko-heading-wrap/scripts/heading-lines.mjs:61–67`은 글자 rect의 top 차이가 6px를 넘으면 새 줄로 본다. `white-space:nowrap`인 한 제목에 40px 글자와 12px 인라인 글자를 섞으면 실제 화면은 한 줄인데 `신규 / 가입 / 혜택`, 구 쪼개짐 1건, 고아 1건, exit 1을 출력한다. `mixed-font-one-line.png`와 재현 결과에 증거가 있다. 글자 크기·기준선 차이와 실제 줄 경계를 구분해야 한다. 이 오탐이 기존 실험 수치를 바꿨다는 증거는 이번 검토에서 확보하지 않았다.

4. **[P2] 재측정 경로에서 폰트 복원이 빠진다.** `experiments/tools/collect-run.sh:11`은 측정 후 run의 fonts 폴더를 삭제한다. `fetch-fonts.sh`는 공용 tools/fonts만 채운다. README의 run HTML에 대한 직접 실행과 `crop-headings.mjs`에는 run별 fonts를 복원하는 단계가 없다. `document.fonts.ready`는 폰트 다운로드 성공을 보장하지 않는다. 복원/로드 검증을 하나의 실행 경로에 넣고 폰트 해시·브라우저 build·조건 프롬프트를 기록해야 한다. 이 코드상의 결함만으로 과거 캡처가 실제 fallback 폰트를 사용했다고 단정할 수는 없다.

5. **[P2] `--json` 출력은 유효한 JSON이 아니다.** `heading-lines.mjs:88–92`는 JSON 배열 뒤에 한국어 요약을 같은 stdout으로 출력한다. 정상 실행도 `JSON.parse(stdout)`가 실패함을 재현했다. 요약은 stderr로 보내거나 JSON 객체 내부에 넣어야 한다.

6. **[P2] 찾지 못한 keep 구를 정상 통과로 처리한다.** `heading-lines.mjs:73–79`는 구가 없으면 조용히 넘어간다. ‘다른 제목’에서 `--keep "신규 가입 혜택"`을 지정하면 ‘구 쪼개짐 0건’과 exit 0이 나온다. 이는 ‘발견된 구는 안 쪼개졌다’라는 좁은 의미로는 맞지만 gold 검증에서는 coverage 누락을 정상으로 오해하게 만든다. 구별 발견 횟수와 unmatched 목록을 출력하고, 고정 gold 검증 모드에서는 누락을 오류로 구분해야 한다.

수정은 신규 유틸 버전으로 진행하고 기존 frozen 결과를 덮어쓰지 않는 것이 좋다. 이번 QA에서는 실험 구현을 수정하지 않았다. 이 보고서와 검증 근거는 별도 커밋으로 등록한다.

**gold 독립 검토**

14개 구 모두 의미가 통하는 구다. 그러나 ‘의미가 통한다’와 ‘절대로 줄 사이에서 나누면 안 된다’는 다르다. 오류로 단일 집계하기보다 강한 보존 선호와 문맥상 선호를 구분할 것을 권한다. 개별 판정은 `gold-review.json`에 있다.

- 보존 우선순위가 높은 후보: `예지 정비`, `멈추기 전에`, `출고 속도`, `고장의 징후`. `예외 상황 처리`도 유용하지만 최소 단위 `예외 상황`과 전체 구를 구분할 수 있다.
- 특히 약한 gold: `오배송이 늘지 않은`은 핵심 명사 `이유`를 제외한다. `오배송이 / 늘지 않은 이유`도 가능한 묶음인데 기존 gold는 이를 일률적으로 불리하게 평가한다.
- `AI 도입 3년 차`는 `AI 도입`과 `3년 차`라는 별도 단위를, `베테랑을 설득하는 법`은 최소 `설득하는 법`을 먼저 지키는 것이 합리적이다. 긴 전체 구는 컨테이너 폭에 따라 선택할 수 있다.
- `현장이 얻은 것`, `데이터를 믿지 않는`, `절반으로 줄이고도` 같은 절 전체를 단단한 nowrap 단위로 요구하면 의미 보존과 줄 길이·글자 크기·넘침 사이의 tradeoff가 생긴다.

수정 gold는 후속 실험 전에 별도 버전으로 고정하고, 과거 gold 수치와 섞지 않아야 한다. 독립 판단 역시 이번 GPT 모델의 판단이며 사용자/별도 한국어 평가자의 합의를 대신하지 않는다.

**blind 평가**

무작위 좌우 키, gold, README, 기존 proxy 결과를 열기 전에 375/768px 원본 제목 PNG를 확인하고 `blind-headings-pre-key.json`에 판정을 저장했다. 먼저 읽은 pairs manifest는 어떤 조건들이 비교되는지는 공개하지만 무작위 좌우 대응은 공개하지 않는다. 주 판정 규칙은 모바일 우선, 모바일 의미 경계가 같을 때 태블릿으로 동률 해소다. 글자 크기 차이만으로 줄바꿈 우열을 정하지 않았다.

P10은 첫 이미지 확인에서 잘못 빈 화면으로 판단했다. 원본 재확인과 픽셀 검사에서 정상 제목 이미지임을 확인했으므로 **빈 자극이라는 주장은 철회한다.** 재확인은 키 공개 후였기 때문에 P10은 독립 blind 집계에서 제외한다. 초기 기록은 감사 이력을 위해 보존하고 `blind-headings-correction.json`을 함께 해석해야 한다. P10의 키 공개 후 판정은 R 선호지만 독립 점수에 포함하지 않았다.

| 비교 | 독립 판정 |
|---|---|
| T1 B vs C, 3쌍 | C 3, B 0 |
| T3 B vs C, 3쌍 | C 3, B 0 |
| T3b B vs C, 3쌍 | C 1, B 2 |
| T3b D vs C, 2쌍 | C 1, D 1; 나머지 1쌍 제외 |

모바일만 보면 B vs C는 C 4, B 2, 동률 3이다. D vs C는 D 1, 동률 1, 1쌍 제외다. 태블릿 동률 해소가 전체 선호에 영향을 주므로 향후 설문은 폭별 응답을 따로 받는 것이 좋다. T3b D/C 비교는 같은 C 산출물을 B/C 비교에서도 사용하므로 독립 표본으로 합산할 수 없다.

같은 12쌍에 대한 기존 Claude 선호 응답은 저장소에서 찾지 못했다. `T1-proxy-panel`은 A/B 전체 페이지 순위라 이번 제목 B/C·D/C 선호와 직접 비교할 수 없다. ‘GPT와 Claude 순위 일치’ 여부는 현재 자료로 판정 불가다. GPT 평가는 한 모델 평가자의 방향 신호이며 사람의 평가를 대체하지 않는다.

**재측정과 재현성**

단위는 원 로그와 같은 ‘gold 구가 하나 이상 쪼개진 제목×폭’이다. 아래 현재 환경 수치는 원 실험을 동일 환경으로 재현한 결과가 아니라, 보존된 HTML을 다른 환경에서 다시 측정한 결과다.

| task/조건 | 원 로그 합계 | 이번 환경 합계 |
|---|---:|---:|
| T1 A/B/C | 9 / 4 / 0 | 10 / 5 / 0 |
| T3 A/B/C | 9 / 6 / 1 | 9 / 10 / 0 |

T3b-C-1의 제목 넘침은 이번 5개 폭 측정에서는 0건이었다. 이 차이를 과거 결과 오류라고 단정할 수 없다. 브라우저·OS·실제 폰트 바이너리와 로드 상태가 고정되지 않았기 때문이다. 쉬운 task의 개선 방향은 남고, 어려운 task에서는 여전히 C run 간 편차가 크다. 원 로그의 ‘10→1’ 같은 정확한 숫자까지 재현됐다고 보고해서는 안 된다.

**권장 진행 순서와 산출물**

1. 사용자 평가 전에 localStorage와 export 식별자를 분리한다. 모바일/태블릿 문항도 나눈다.
2. 검사기의 소형 타깃 간격, 실제 줄 구분, JSON 출력, gold coverage를 고치고 현재 재현 예제로 확인한다.
3. 원 Chromium build와 폰트 해시를 기록하고 run 폰트 복원을 자동화한다. 변경된 유틸로 새 결과를 별도 저장한다.
4. gold 대안 경계를 별도 버전으로 고정한 뒤 독립 사람 평가를 수집한다. 그때까지 experimental 상태를 유지한다.

재현 코드: `reproduce.mjs`, `corpus-headings.mjs`. 결과: `reproduction-results.json`, `corpus-T1-T3.json`, `corpus-T3b.json`. blind 원기록·정정 및 gold 판정도 같은 폴더에 있다. 등록용 재현 코드는 특정 기기의 절대 경로를 제거하고 환경 변수와 이 폴더를 기준으로 경로를 찾도록 정리했다. 실행 안내는 README.md에 있다. 결과 기록은 최초 QA 실행에서 나온 그대로이며 실험 구현은 변경하지 않았다.
